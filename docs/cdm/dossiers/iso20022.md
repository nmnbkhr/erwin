# ISO 20022 — Stage 0 Model Dossier

## Identity
- **Model**: ISO 20022 Universal Financial Industry Message Scheme —
  specifically the **Financial Repository** content (business process
  catalogue, data dictionary, message definitions), not the standard documents.
- **Publisher**: ISO TC68; repository operated by the ISO 20022 Registration
  Authority (SWIFT as RA).
- **Host workbench**: BAIW, as a second descriptor alongside FSDM — the
  composite pattern already proven by HCDM-over-FHIR in HAIW.

## Version (verified 2026-08-28)
- The standard itself: current edition comprises nine parts, published
  April 2026, available for purchase (PDF/paper). We do **not** need to
  purchase these for repository extraction; they matter only if we later quote
  metamodel definitions.
- The repository content is continuously maintained; the e-Repository
  download is the pinnable artifact. **versionPin is set at download time**
  (first act of CDM-P2 Stage 1) using the repository publication identifier on
  the artifact actually retrieved.

## License analysis (basis of regime)
- Source: iso20022.org Intellectual Property Rights page, verified 2026-08-28.
- Contributing organizations retain their IPR but grant third parties a
  **non-exclusive, royalty-free license to use the published repository
  information**. This is a *use* license; it is not an explicit
  redistribution/open-source license in the Apache/CC sense.
- Ruling → regime `open-use-restricted`:
  - MAY ship: business-area structure, message-set identifiers, component
    names, our own paraphrased descriptions, and mappings — all with
    provenance, `method: 'derived'` for paraphrase, `verbatim` acceptable for
    names/identifiers.
  - HOLD: bulk verbatim reproduction of definition texts. Not needed for
    Stages 1–3; revisit with a specific legal note only if a use case demands
    verbatim definitions.
- No membership or fee for repository access.

## Distribution & extraction tooling
- e-Repository is provided in **EMF format with the ISO 20022 ecore
  implementation metamodel** (Eclipse toolchain). Official browsing route is
  an Eclipse plugin generated from the metamodel; there is a documented
  performance workaround for opening the repository.
- Extraction plan: treat the .ecore/EMF XMI as XML and extract with a script
  rather than the Eclipse UI — subject-area (business area) and message-set
  structure is retrievable by direct parse. Fall back to the online
  repository browser for spot verification. The extraction script lives in
  the repo and its output is what provenance locators point into
  (locator = repository path/id, not "the script").
- Web-facing alternative for Stage 1 verification: the online Repository
  search on iso20022.org.

## Update cadence
- Repository updated on message-release cycles through the RA's maintenance
  process (SEG-approved change requests). Annual-ish message releases;
  exact cycle noted at pin time. Stage 4 re-enrichment should align to a
  release, not a calendar date.

## Commercial pull
- SBP payments modernization and ISO 20022 migration pressure on Pakistani
  banks (RTGS/instant-payments alignment); global SWIFT MT→MX migration makes
  every BAIW client a current or imminent ISO 20022 adopter.
- BAIW story: FSDM answers "how the bank's data warehouse is organized";
  ISO 20022 answers "how money movement is described on the wire" — the
  mapping between the two IS the product (e.g. which repository business
  areas touch which FSDM subject areas feeding COE cash positioning).

## Risks / open items
- OI-1: pin mechanics — confirm at download which publication identifier the
  RA stamps on the e-Repository artifact.
- OI-2: ecore parse may surface a deeper hierarchy than "business area →
  message set"; Stage 1 decision rule: subject areas = business areas, one
  level, resist the temptation to import the full catalogue depth at Stage 1.
- OI-3: quoting metamodel-level definitions would require the purchased
  standard parts; avoid by paraphrase.
