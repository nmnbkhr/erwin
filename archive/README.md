# archive/

Material that is **not part of the running application**. The app is `baiw/`;
nothing in this folder is read by its build, dev server, or deploy.

That claim was tested rather than assumed. Every entry formerly at the repo root
was grepped against the full app surface — `baiw/src`, `baiw/public`,
`baiw/scripts`, `baiw/.github`, `index.html`, all four tsconfigs,
`vite.config.ts`, `eslint.config.js`, `vercel.json`, `netlify.toml`, both
`.gitignore`s, both `dev.sh`s and both `package.json`s. Four entries came back
referenced; they are in [`../data-sources/`](../data-sources/), not here.

Everything was relocated with `git mv`, so `git log --follow` still works on any
file in this folder.

## What is in each folder

| Folder | Contents | Notes |
|---|---|---|
| `build-prompts/` | 43 prompt documents used to generate the app modules, the PowerPoint decks and the analysis pipelines | Input to an assistant, never to a compiler |
| `design-docs/` | 8 design documents, execution guides and portfolio analyses | Includes the repo's original `OVERVIEW.md` |
| `pipeline-scripts/` | 37 Python scripts — the BACR, BVF and FSDM analysis phases, the erwin/XSD parsers, and the PowerPoint slide generators | **See the path warning below** |
| `pipeline-output/` | `bvf_output/`, `erwin_parser_output/` | Generated by the scripts above. Not read by the app |
| `source-documents/` | The source decks, workbooks, PDFs, `tds.xsd` and the 132 MB erwin model | Gitignored by extension; present on disk only |
| `pptx-authoring/` | `pptout/` (the generated decks, tracked) and 12 `unpacked_*/` working directories | `unpacked_*` is gitignored and regenerable from the decks |
| `prototypes/` | Two standalone `.jsx` files that predate the app | Superseded by `baiw/src` |
| `misc/` | `runit`, `biapp.sh`, `wco_data_model_architecture.svg`, `__pycache__` | `runit` and `biapp.sh` are dead — see below |

## Path warning — these scripts were already broken before the move

Every script in `pipeline-scripts/`, plus `misc/runit` and `misc/biapp.sh`,
hardcodes an absolute `/mnt/e/erwin/...` path. That was the old NTFS checkout.
This repository lives on ext4 at `~/erwin`, so **those paths have not resolved
for some time** — the move did not break them, and moving them back would not
fix them.

If you need to re-run one, the fix is to replace the hardcoded root:

```python
OUTPUT_DIR = '/mnt/e/erwin/bacr_output'
# becomes, relative to this file:
OUTPUT_DIR = Path(__file__).resolve().parents[1] / 'pipeline-output' / 'bacr_output'
```

`baiw/scripts/prepare_data.py` is the exception and is deliberately **not** in
this folder: it takes its input root as `--repo`, which is why relocating its
inputs required no code change. It is invoked by `./dev.sh data`.

## Deleting this folder

Safe as far as the application is concerned — `npm run build` and
`npm run check:dgiw` do not touch it. You would lose the provenance of the
datasets in `baiw/src/data/` and the ability to regenerate the decks. Note that
`source-documents/` is gitignored, so deleting it loses those files permanently.
